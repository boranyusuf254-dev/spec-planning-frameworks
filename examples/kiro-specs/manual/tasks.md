# Implementation tasks: reliable webhook delivery

> Manual, source-faithful example — not generated by Kiro.

- [ ] 1. Define delivery domain types and state transitions
  - Model tenant, endpoint, event, delivery, attempt, dead-letter, replay, and audit records.
  - Encode allowed delivery transitions and terminal states.
  - _Requirements: 2.2, 3.2, 3.3, 4.2, 5.1_

- [ ] 2. Implement tenant-scoped persistence
  - Add durable schemas and migrations.
  - Add atomic due-delivery claiming and tenant-bound queries.
  - Test concurrent claims and cross-tenant denial.
  - _Requirements: 2.3, 5.1, 5.2_

- [ ] 3. Implement outbound signing
  - Resolve the signing and rotation decision.
  - Build canonical request bytes and signature metadata.
  - Add positive and tamper-failure tests.
  - _Requirements: 1.1, 1.2, 1.3_

- [ ] 4. Implement the delivery worker
  - Send a claimed request with stable event identity.
  - Store a bounded immutable attempt result.
  - Stop on success and classify failures.
  - _Requirements: 2.1, 2.2, 3.2, 3.4, 4.2_

- [ ] 5. Add retry scheduling and dead-letter transitions
  - Resolve retryable failures, limits, and caps.
  - Calculate exponential backoff with jitter.
  - Move exhausted deliveries into dead-letter state.
  - Test timing bounds, concurrency, and exhaustion.
  - _Requirements: 3.1, 3.2, 3.3, 3.4_

- [ ] 6. Add audit queries and manual replay
  - Authorize tenant-scoped delivery history and dead-letter reads.
  - Create replay requests linked to the original trail.
  - Test that replay adds rather than rewrites history.
  - _Requirements: 4.1, 4.2, 4.3, 5.1, 5.2_

- [ ] 7. Add delivery observability
  - Emit attempt, outcome, retry, dead-letter, and latency metrics.
  - Add safe structured logs and trace correlation.
  - Verify secret and response-body redaction.
  - _Requirements: 6.1, 6.2_

- [ ] 8. Build the end-to-end acceptance suite
  - Run a controllable receiver through signing, duplicates, retries, dead letters, replay, audit, and tenant-boundary scenarios.
  - Assert observable signals for each path.
  - _Requirements: 6.3 and all preceding requirements_
